# Tangent Fixer — 詳細仕様

## 概要
- バージョン: 0.2.1 / 対応Maya: 2024+
- カテゴリ: Animation
- 表示場所: シェルフボタン `TanFixer`（左クリックで起動）
- Fカーブのタンジェントを、中間キーは前後のキーを通る曲線の接線に・極値は
  フラットにし、キーに無いオーバーシュートを作らない形に一括で直す。

## 解決したい課題

| 既定のタンジェント | 課題 |
|---|---|
| Auto | 最大値と最小値の間に置いたキーで、傾きの制限が左右非対称に効き、カーブが少し歪む |
| Spline | 前後のキーを結ぶ傾きをそのまま使うので、キーとして打っていないオーバーシュートが出る |

### 設計判断

- **Steffen 法（1990）を使う。** Maya の非ウェイトタンジェントはハンドル長が
  区間の 1/3 固定で、3 次エルミート補間と同値。 Steffen 法はその傾きを
  1. 前後の区間の傾きを**区間長で重み付けした**平均（前後のキーを通る放物線の傾き）に取り、
  2. 左右の区間の傾きの 2 倍で頭打ちにする

  ことで、**各区間で両端キーの値の範囲からはみ出さない**（単調性）ことを保証する。
  前後で傾きの符号が変わるキー（極値）と、どちらかが平らなキーは自動で 0。
- **頭打ちは 3 倍（v0.2.0 から既定）。** 原論文の 2 倍は、片側の区間が緩いと
  接線より寝た傾きになり「歪み」に見える（実機での報告）。 区間の両端の傾きが
  どちらも区間の傾きの 3 倍以内ならはみ出さない（Fritsch–Carlson の十分条件）ので、
  3 倍でもはみ出し 0 は保たれ、接線がそのまま使える範囲が広がる。
  Method で `Tangent`（頭打ちなし）/ `Strict`（2 倍）も選べる。
  入出力を同じ傾きにするので C1 連続（キー位置で折れない）。
  Fritsch–Carlson より式が局所的で、反復の調整が要らない。
- **入出力のタンジェントは Fixed + lock。** Auto / Spline のままだと Maya が
  キー編集のたびに再計算して元に戻るため。
- **選択キーだけ直しても、傾きの計算にはカーブ全体を使う。** 選択範囲の端の
  キーも、範囲外の隣のキーとのつながりを保つ。
- **角度の単位はカーブの型ごとに一時カーブで実測する。** タンジェント角が「秒基準か」
  「回転カーブは度かラジアンか」を開発機で確かめられない（CLAUDE.md
  「推測で直さない」）。 同じ型の animCurve を一時的に作って 2 キーを打ち、
  出力タンジェントを Linear にすると隣のキーへの直線になるので、その角度と
  傾きから倍率を逆算する（`core.scale_from_measurement`）。 一時カーブは同じ
  undo チャンク内で消す。 測れないときは
  「秒基準」の仮定（傾き × fps）に落として**止めずに続ける**（安全弁で主機能を止めない）。
  使った倍率は Script Editor に `measured` / `fallback` 付きで出る。
- **ユーザーのキーには最終結果以外の変更を入れない（v0.2.1）。** v0.2.0 までは
  ユーザーのキーを測定のために一時的に Linear にしていた。 入出力の型が
  食い違った瞬間に Maya がタンジェントを break し、その**暗黙の変更は undo で
  戻らない**ため、Ctrl+Z 後に break 状態が残った（実機での報告）。
  ロックも同じ理由で、元からロックされているキーには触らない（入出力に同じ
  角度を書くだけでロックは保たれる）。 break されていたキーだけ明示的に lock する
  （明示的な変更なので undo で break に戻る）。
- **段差（Stepped / Stepped Next）の出力タンジェントのキーは触らない。**
- **ウェイト付きタンジェントのカーブはウェイトを変えない。** 角度だけ書くので、
  ハンドル長によってははみ出しが残る。 警告で知らせる。

## 機能詳細

### 1. Fix Tangents（`ui.fix` / `tangent_fixer.fix()`）
- 対象: Graph Editor で選択したキー。 無ければ選択オブジェクトの全カーブの全キー
- Method（中間キー）: `Smooth`（接線・3 倍で頭打ち・既定）/ `Tangent`（接線そのもの。
  極値だけ水平。 わずかにはみ出し得る）/ `Strict`（2 倍で頭打ち。 v0.1.0）。
  optionVar `ntk_tangent_fixer_method`
- 端のキー: `Flat`（水平・既定）/ `Natural`（端から 3 キーの放物線の傾き。
  はみ出さない範囲に頭打ち。 2 キーだけのカーブは直線）。 optionVar
  `ntk_tangent_fixer_end_mode` に保存
- 全体で 1 undo。 1 本のカーブで失敗しても他は続け、警告に出す

### 2. 調査関数（`tangent_fixer.probe()`）
- `probe()` — 選択中のカーブのキーごとのタンジェント値（型・角度・x/y・ウェイト）と、
  Linear のキーについて実測倍率と仮説（frame / sec / sec+rad）を並べて出す。
  シーンを変更しない
- `probe(try_it=True)` — 型ごとの倍率の実測値と、一時ノード `ntk_tangent_fixer_probe`
  の山のキーに Fix → `undo` を掛けて**元の状態に戻るか**（`UNDO MATCH` / `DIFF`）を
  出して消す。 Fix の undo を 1 つ消費する

## 実装状況

### v0.2.1
- Ctrl+Z で戻すとタンジェントが break 状態で残る不具合を修正（推定原因: 測定のために
  ユーザーのキーを一時的に Linear にしたことによる暗黙の break）。 倍率の測定を
  一時カーブに移し、元からロックされているキーの lock には触らないようにした。
- **実機未確認。** 原因の推定が外れていれば `probe(try_it=True)` が `UNDO DIFF` を出す。

### v0.2.0
- Method（Smooth / Tangent / Strict）を追加し、既定を Smooth（3 倍で頭打ち）に変更。
  v0.1.0 の「Natural にしても少し歪む」への対応。
- **実機未確認。** 歪みの原因が頭打ち以外（ウェイト付きタンジェント・角度の倍率）
  だった場合は直らない。 `probe()` の出力で切り分ける。

### v0.1.0
- Steffen 法による Fix Tangents、端のキーの Flat / Natural、選択キー優先の対象決定、
  カーブごとの倍率の実測、調査関数 `probe()`。
- テスト: `core` の単体（ランダム 300 カーブではみ出し 0 を含む）と、偽のカーブでの
  `fix()` の一往復。
- **実機未確認。** 特に次の 2 点は自宅で確かめられない:
  - Linear にしたタンジェントの角度が隣のキーへの直線になる（倍率の実測の前提）
  - 回転カーブで角度の単位がずれないか（実測で吸収される想定）
