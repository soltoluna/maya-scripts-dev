# Tangent Fixer — 変更履歴

現時点の仕様と確定した設計判断は `SPEC.md` を参照。 ここではバージョンごとの
経緯・試行錯誤・不具合修正の細部を記録する。 降順（新しい順）。

## 0.3.0 — Smooth をキーの前後で曲率までつなぐ形に変更
- 実機で「1f=0 / 5f=2.5 / 10f=5 で、5f の前後をなめらかにしたい」との要望。
- v0.2 の Smooth は前後のキーを通る放物線の接線（0.569）で、傾きは連続（C1）だが
  2 階微分は 5f の前後で -0.37 → +0.14 と切り替わる。 端が Flat だとこの差が目立つ。
- 対処: 極値で区切った区間ごとに C2 の 3 次スプラインを解く（5f は 0.854、曲率の差 0）。
  解いた後にはみ出し防止の頭打ち（3 倍）を掛ける。
- v0.2 の Smooth は `Local` に改名して残し、`Tangent`（頭打ちなし）は廃止。
- 実機未確認。

## 0.2.1 — Ctrl+Z 後にタンジェントが break で残る不具合を修正
- 実機で「Ctrl+Z で処理前に戻すとタンジェントが break 状態になっている」との報告。
- 推定原因: 倍率の実測のために**ユーザーのキー**の出力タンジェントだけを一時的に
  Linear にしていた。 入出力の型が食い違うと Maya が暗黙にタンジェントを break し、
  その暗黙の変更は undo の記録に残らない。 続く `lock=True` の undo は「その時点の
  状態（= break）」に戻すだけなので、最後に break が残る。
- 対処: 倍率は同じ型の一時 animCurve で測る（ユーザーのキーには触らない）。
  元からロックされているキーの lock は操作しない。
- 推定の当否は `probe(try_it=True)` の `UNDO MATCH` / `DIFF` で実機から確かめる。
- 実機未確認。

## 0.2.0 — 接線を優先する Method を追加
- 実機で「Natural にしてもカーブが少し歪む」との報告。 Natural は端のキーだけの
  設定で、中間キーの歪みは Steffen 法の頭打ち（区間の傾きの 2 倍）が原因と判断。
  片側の区間が緩いと、接線より寝た傾きになる。
- Method を追加: `Smooth`（既定。 接線を使い、はみ出す場合だけ 3 倍で頭打ち。
  Fritsch–Carlson の十分条件なのではみ出し 0 は維持）/ `Tangent`（接線そのもの。
  極値だけ水平）/ `Strict`（v0.1.0 の挙動）。 optionVar `ntk_tangent_fixer_method`。
- 実機未確認。 歪みの原因が頭打ちでなく、ウェイト付きタンジェントや角度の倍率に
  ある可能性は残っている（`probe()` の出力で切り分ける）。

## 0.1.0 — 初版（Steffen 法で Fix Tangents）
- Auto（山と谷の間のキーで歪む）と Spline（打っていないオーバーシュート）の
  課題を、Steffen 法の単調 3 次補間で解く。
- タンジェント角の単位が開発機で確かめられないので、カーブごとに 1 キーを
  Linear にして角度を実測し、倍率を逆算する方式にした。 測れないときは秒基準の
  仮定に落とす。 実機の値は `probe()` で持ち帰る。
- 実機未確認。
