# BlendShape Manager — 詳細仕様

## 概要
- バージョン: 0.1.0 / 対応Maya: 2024+
- カテゴリ: Rigging
- 表示場所: シェルフボタン `BSManager`（左クリックで起動）
- ブレンドシェイプの作成・ターゲットの追加 / 削除・ウェイト操作・リネーム
  （一括を含む）・インビトウィーンの追加・左右反転したターゲットの作成を
  1 つのウィンドウで行う。

## アーキテクチャ

```
../install.py       リポジトリ直下のハブ。 全ツールをまとめて配る（触らない）
blendshape_manager/
  __init__.py       __version__（版数の唯一の情報源）/ SHELF_LABEL / show()
  core.py           Maya 非依存の純ロジック ← 自宅でテストできるのはここだけ
  scene.py          cmds / OpenMaya でシーンを読み書きする。 diagnose() もここ
  ui.py             cmds による UI。 値を集め、core で検証し、scene に流すだけ
  dev_tools.py      バージョン表示と「GitHub から更新」（全ツール共通・触らない）
```

### 設計判断

- **UI は `maya.cmds`。** 2024（PySide2）と 2025（PySide6）を 1 本で動かすため。
- **ベースは blendShape の 1 本目のジオメトリだけを扱う**（`inputTarget[0]` /
  `outputGeometry[0]`）。 1 ノードに複数メッシュをぶら下げた構成は対象外。
- **ターゲットの一覧はエイリアス（`aliasAttr`）とウェイトの番号から作る。**
  エイリアスの無い番号は `weight[i]` と表示する。 解釈は `core.parse_alias_list`
  / `core.target_entries`。
- **新しいターゲットの番号は「既存の最大 + 1」。** 抜けた番号は埋めない
  （削除済みターゲットの残骸と番号がぶつかるのを避ける）。
- **リネームは `core.plan_renames` で手順を組み立ててから実行する。**
  `L_smile ↔ R_smile` の入れ替えや連鎖は、そのまま順に付けると途中で同名が
  できて `aliasAttr` が失敗する。 衝突するときだけ一時名を経由する 2 段にする。
- **削除は Shape Editor と同じ MEL 手続き `blendShapeDeleteTargetGroup` を
  優先する。** 無い・失敗したときは警告して、エイリアス除去 +
  `removeMultiInstance` で直接外す（安全弁で削除を止めない）。
- **ミラーは Maya の flip / mirror フラグを使わず自前で計算する。**
  スライダーを「対象だけ 1、他は 0、envelope 1」にして blendShape の出力
  （`outputGeometry[0]`、オブジェクト空間）を読み、ニュートラルとの位置で
  左右の頂点を対応させて反転する（`core.build_mirror_map` / `core.mirror_shape`）。
  計算が `core` にあるので自宅でテストでき、他のデフォーマ（スキン等）の影響も
  受けない。 つながっているスライダーは一時的に外して、終わったらつなぎ直す。
  - 反対側の名前は `core.mirror_name`（`L_`/`R_`、`_L`/`_R`、`Left`/`Right` など）。
    当たらなければ `<名前>_mirror`
  - 反対側が見つからない頂点は動かさず、個数をダイアログで知らせる
  - 左右の組が両方チェックされていたら先に出てきたほうだけ処理する
    （`core.plan_mirror`）
- **シーンを変える操作は 1 操作 = 1 undo チャンク。** `ui._action` が
  チャンクの開閉・エラーダイアログ・一覧の作り直しをまとめて行う。
- **ウェイトのスライダーは `attrFieldSliderGrp` で属性に直接つなぐ。**
  scriptJob を張らないので、後片付けの漏れが起きない。 その代わり、
  外でターゲットを増減したときは「更新」を押す。
- **実機の戻り値の確認用に `scene.diagnose(bs)` を持つ。** シーンを変更せず、
  失敗は `<ERROR ...>` を値にして最後まで出す。

## 機能詳細

### 1. 作成
- ターゲット → ベースの順に選んで「選択から作成」。 ベースだけでもよい（空の
  blendShape ができる）
- ノード名が空なら `<ベース名>_BS`。 「Front of chain」で他のデフォーマより前に入れる
- 頂点数がベースと違うメッシュがあれば作らずに一覧を出す

### 2. ノードの選択
- メニューにシーン内の blendShape を並べる。 「選択から」で選択メッシュの
  ヒストリから探す。 最後に選んだノードを覚えておく

### 3. ターゲットの一覧
- 1 行 = チェックボックス（名前、インビトウィーンがあれば `(+n)`）+ ウェイトの
  スライダー
- 絞り込み（部分一致・大文字小文字無視・空白区切りで OR）、全チェック / 全解除
- 「選択メッシュをターゲットに追加」「チェックしたものを削除」
- 「チェック → 0 / 1」「表示中を全部 → 0」。 接続・ロック中のスライダーは飛ばす

### 4. 名前
- チェックした 1 つをリネーム
- 一括リネーム: 検索置換 → 接頭辞 → 接尾辞 の順に適用。 対象はチェックした
  もの、無ければ表示中の全部

### 5. インビトウィーン
- 選択したメッシュを、チェックした 1 つのターゲットに重みを指定して追加する
  （0 < 重み < 1、既にその重みがあれば弾く）

### 6. ミラー
- チェックしたターゲットごとに、左右反転したターゲットを作る
- 対称軸（X / Y / Z、オブジェクト空間）と許容誤差を指定する
- 反対側の名前が既にあれば、オプションに従って上書き（形を置き換える）か中止

## 実装状況

### v0.1.0
- 上記 1〜6 を実装。 `core` のテスト（名前・リネーム計画・インビトウィーン・
  ミラー計算）と、`scene` を差し替えた UI の往復テストが通る。
- **実機未確認。** 特に確かめたいもの:
  - `blendShapeDeleteTargetGroup` の呼び出し形（失敗すれば直接削除に落ちる）
  - `aliasAttr` で既存のエイリアスを付け替えられるか
  - ミラー: `outputGeometry[0]` を一時メッシュにつないで読めるか、上書き時に
    `blendShape -e -t` で既存の番号の形が置き換わるか
  - `attrFieldSliderGrp(minValue/maxValue/columnWidth3)` の見た目
- 既知の制約: ベースが左右対称でないとミラーの対応が取れない。
  上書きミラーは既存のインビトウィーンを作り直さない。
