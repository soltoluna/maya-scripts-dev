# Color Override — 詳細仕様

## 概要
- バージョン: 0.2.0 / 対応Maya: 2024+
- カテゴリ: Utility
- 表示場所: シェルフボタン `ColorOvr`（左クリックで起動）
- 選択したオブジェクトを任意の色でフラットに塗り分け、同系色のオブジェクトの
  貫通（めり込み）をビューポートで見分けられるようにする。 色は**一時的に
  外して元のマテリアルを見る**ことができ、記録ごと片付けることもできる。

## 背景 — なぜレンダーレイヤーでやらないのか

「オブジェクト ID を出す」だけなら Render Setup + Arnold の `aiUtility`
（Color Mode: Object）が本筋だが、**目的がビューポートでの目視確認**なので合わない。

| 方法 | ビューポートに出るか | 対象ごとに色を変えられるか |
|---|---|---|
| Render Setup のシェーダーオーバーライド | 出る | **collection 単位**。 対象の数だけ collection が要る |
| Arnold `aiUtility`（Object） | **出ない**（ARV / レンダリングのみ） | 出る |
| **直接 `surfaceShader` を割り当てる（本ツール）** | 出る | 出る |

Render Setup を経由すると、ルック開発と同じレイヤー構造を確認目的で汚すことにも
なる。 確認用の一時的な塗り分けなので、**シェーダー割り当てを直接触って、
元に戻せるようにする**ほうが素直になる。

`surfaceShader` を選んだのはライティングに影響されないフラットな色になるため。
陰影が乗ると同系色のグラデーションに境界が埋もれるので、ID 表示としては
`lambert` より適している。

## アーキテクチャ

```
../install.py       リポジトリ直下のハブ。 全ツールをまとめて配る（触らない）
color_override/
  __init__.py       __version__（版数の唯一の情報源）/ SHELF_LABEL / show()
  core.py           Maya 非依存の純ロジック ← 自宅でテストできるのはここだけ
  ui.py             cmds による UI とシェーダー割り当ての操作
  dev_tools.py      バージョン表示と「GitHub から更新」（全ツール共通・触らない）
```

`core.py` が持っているもの:

| 関数 | 役割 |
|---|---|
| `color_at` / `distinct_colors` | 識別色の生成（色相を黄金比でずらす） |
| `parse_hex` / `to_hex` | 16 進カラーと RGB の往復 |
| `short_name` / `sanitize_identifier` / `override_node_names` | ノード名の組み立てと無害化 |
| `match_records` / `format_row` / `next_start_index` / `unique` | 記録の突き合わせと表示 |
| `index_by_object` / `any_enabled` / `group_by_original` | 一時解除の判断と、`cmds.sets` の呼び出しをまとめるグルーピング |
| `join_members` / `split_members` | メンバー一覧と文字列属性の往復 |

`ui.py` に残しているのは `cmds` の呼び出しだけで、判断はすべて `core` にある。

### オーバーライドの持ち方

対象 1 つにつき `surfaceShader` + `shadingEngine` を 1 組作る。

```
ntk_color_override_<対象名>_SHD    surfaceShader（outColor が表示色）
  .ntkColorOverrideOriginal        元の shadingEngine 名 ← 復元の情報源
  .ntkColorOverrideTarget          掛けた時点の対象ノード名（一覧の表示用）
  .ntkColorOverrideMembers         掛けた相手 ← 一時解除から戻す情報源
ntk_color_override_<対象名>_SG     上をつないだ shadingEngine
```

### 設計判断

- **復元の情報はシーンに書く。** Python 側の辞書に持つと、シーンを保存して
  開き直した時点で戻せなくなる。 シェーダーの文字列属性に書いておけば
  シーンと一緒に保存され、次に開いたときも Restore が効く。
- **管理対象の判別は名前ではなく属性の有無で行う。** `.ntkColorOverrideOriginal`
  があるシェーダーだけを対象にするので、ユーザーがノードをリネームしても
  追跡できる。 名前で判別すると、リネームされた瞬間に孤児になる。
- **掛け直しのときは既存のオーバーライドを先に探す。** そうしないと
  「オーバーライド用の SG」を「元の SG」として記録してしまい、**二度と元の
  マテリアルに戻せなくなる**。
- **既存の照会はシーンの割り当てではなく記録の索引から行う**
  （`core.index_by_object`）。 v0.2.0 で一時解除を入れた結果、**解除中は対象が
  元の SG に戻っている**ので、割り当てを辿ると既存のオーバーライドを
  見つけられない。 見つけ損なうと 2 本目のシェーダーを作ってしまう。
  索引は 1 回のスキャンで作るので、対象ごとに `listConnections` を辿るより速い。
- **色は乱数ではなく色相を黄金比でずらして生成する。** 等間隔にすると周期で
  色が戻って 10 個目と 20 個目が同色になり、乱数にすると掛け直すたびに
  色が入れ替わって「さっきと同じものを見ている」確信が持てなくなる。
- **シーンに作るノードにも名前空間（`ntk_`）を付ける。** 実機のシーンには
  他の人が作ったノードも同居するため（CLAUDE.md「ルール」）。
- **ウィンドウ名は `<NAMESPACE>_<モジュール名>Win` 固定。** ハブがこの規則で
  古いウィンドウを閉じる。

## 機能詳細

### 1. 任意色のオーバーライド
- カラースライダ、または `#RRGGBB` のテキスト入力で色を決める
- **Apply to Selected** — 選択中のオブジェクトすべてにその色を掛ける
- 既にオーバーライドが掛かっている対象には、**色だけを差し替える**
  （シェーダーを二重に作らない）
- 使った色は optionVar `ntk_color_override_last_color` に控え、次回起動時に復元

### 2. ランダム一括
- **Random → Selected** — 選択物に互いに見分けやすい色を振る
- **Random → All Meshes** — シーンの全メッシュに同上。
  `_BULK_CONFIRM_THRESHOLD`（50）を超えたら確認ダイアログを出す
- 既にオーバーライド済みの数を開始インデックスにするので、後から足した
  オブジェクトにも既存と重なりにくい色が付く

### 3. 一時解除（peek）
- **Hide Colors / Show Colors** — 色を一時的に外して元のマテリアルを見る。
  もう一度押すと掛け直す
- `Restore` との違いは**シェーダーとセットを消さないこと**。 記録が残るので
  何度でも往復でき、色を振り直す必要が無い
- **解除中かどうかのフラグは持たない。** shadingEngine にメンバーが居るかどうかが
  そのまま状態なので、Maya 側で手作業に割り当てを変えられても表示と食い違わない
- 解除中は shadingEngine が空になり「何に掛かっていたか」がシーンから読めなく
  なるので、外す直前に `.ntkColorOverrideMembers` へ控える
- 戻し先が同じものは 1 回の `cmds.sets` にまとめる（`core.group_by_original`）。
  対象ごとに呼ぶと数百オブジェクトで往復が効いてくる
- `color_override.toggle()` はウィンドウを開いていなくても動くので、
  **ホットキーやシェルフボタンに割り当てられる**
- 解除中に `Apply` すると、その対象だけ掛け直して色を出す
  （掛けたのに何も変わらないほうが分かりにくいため）

### 4. 一覧と復元
- ウィンドウ中段にオーバーライド中の対象を `短い名前   #RRGGBB` で一覧表示
- 一覧はシーンの実態から毎回作り直す（キャッシュを持たない）
- 行を選ぶとシーン側でも選択される
- **Restore Selected** — 一覧で選んだ行、無ければシーンで選択中のものを戻す
- **Restore All** — シーン内のオーバーライドを全部戻す
- 元の shadingEngine が既に消えていた場合は `initialShadingGroup` へ逃がす
- 戻したあとはオーバーライド用のシェーダーとセットを削除する

### 5. undo
- 掛ける／戻すはそれぞれ 1 操作 = 1 undo チャンクにまとめる
- 例外が出ても `finally` で必ず閉じる（閉じ忘れると以降の undo が壊れ、
  Maya を再起動するまで直らない）

## 制約・未対応

- リファレンスされたモデルへの割り当ては **2026-09-13 に Maya 2024 で確認済み**。
  ただし**ロックされたノード**は未検証で、割り当ての編集が禁止されていれば
  `cmds.sets` がエラーになる可能性が残る
- インスタンスされたシェイプは考慮していない（1 つ塗ると全インスタンスに乗る）
- フェース単位の割り当て（マルチマテリアル）には未対応。 オブジェクト全体に
  1 色を掛ける。 元がフェース割り当てだった場合、Restore で最初の
  shadingEngine 1 つに寄ってしまう可能性がある（実機確認の項目）
- `surfaceShader` 固定。 陰影付き（`lambert`）への切り替えは未実装
