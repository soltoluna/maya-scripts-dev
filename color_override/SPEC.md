# Color Override — 詳細仕様

## 概要
- バージョン: 0.7.0 / 対応Maya: 2024+
- カテゴリ: Utility
- 表示場所: シェルフボタン `ColorOvr`（左クリックで起動）
- 選択したオブジェクトを任意の色でフラットに塗り分け、同系色のオブジェクトの
  貫通（めり込み）をビューポートで見分けられるようにする。 **1 回の Apply =
  1 セット**として名前を付けて管理し、一時解除・片付け・掛け直しができる。
  片付けた色分けはシーンの隣の JSON に残るので、後からいつでも呼び戻せる。

## 背景 — なぜレンダーレイヤーでやらないのか

「オブジェクト ID を出す」だけなら Render Setup + Arnold の `aiUtility`
（Color Mode: Object）が本筋だが、**目的がビューポートでの目視確認**なので合わない。

| 方法 | ビューポートに出るか | 対象ごとに色を変えられるか |
|---|---|---|
| Render Setup のシェーダーオーバーライド | 出る | **collection 単位**。 対象の数だけ collection が要る |
| Arnold `aiUtility`（Object） | **出ない**（ARV / レンダリングのみ） | 出る |
| **直接 `surfaceShader` を割り当てる（本ツール）** | 出る | 出る |

Render Setup を経由すると、ルック開発と同じレイヤー構造を確認目的で汚すことにも
なる。 確認用の一時的な塗り分けなので、**シェーダー割り当てを直接触って、
元に戻せるようにする**ほうが素直になる。

`surfaceShader` を選んだのはライティングに影響されないフラットな色になるため。
陰影が乗ると同系色のグラデーションに境界が埋もれるので、ID 表示としては
`lambert` より適している。

## アーキテクチャ

```
../install.py       リポジトリ直下のハブ。 全ツールをまとめて配る（触らない）
color_override/
  __init__.py       __version__（版数の唯一の情報源）/ SHELF_LABEL / show()
  core.py           Maya 非依存の純ロジック ← 自宅でテストできるのはここだけ
  ui.py             cmds による UI とシェーダー割り当ての操作
  dev_tools.py      バージョン表示と「GitHub から更新」（全ツール共通・触らない）
```

`core.py` が持っているもの:

| 関数 | 役割 |
|---|---|
| `color_at` / `distinct_colors` | 識別色の生成（色相を黄金比でずらす） |
| `parse_hex` / `to_hex` | 16 進カラーと RGB の往復 |
| `short_name` / `sanitize_identifier` / `override_node_names` | ノード名の組み立てと無害化 |
| `match_records` / `next_start_index` / `unique` | 記録の突き合わせ |
| `group_by_set` / `new_set_name` / `normalize_set_name` / `swatch_colors` | セットへの畳み込みと色見本 |
| `catalog_to_text` / `catalog_from_text` / `merge_catalog` / `backup_path_for` | 控え（JSON）の読み書き |
| `index_by_object` / `any_enabled` | 一時解除の判断と、既存オーバーライドの照会 |
| `align_originals` / `group_by_original` | メンバーごとの戻し先を揃え、`cmds.sets` の呼び出しをまとめる |
| `join_members` / `split_members` | メンバー一覧と文字列属性の往復 |

`ui.py` に残しているのは `cmds` の呼び出しだけで、判断はすべて `core` にある。

### オーバーライドの持ち方

対象 1 つにつき `surfaceShader` + `shadingEngine` を 1 組作る。

```
ntk_color_override_<対象名>_SHD    surfaceShader（outColor が表示色）
  .ntkColorOverrideOriginal        元の SG（旧形式・管理対象の目印を兼ねる）
  .ntkColorOverrideTarget          掛けた時点の対象ノード名（一覧の表示用）
  .ntkColorOverrideMembers         掛けた相手（シェイプ）
  .ntkColorOverrideOriginals       **それぞれの戻し先** ← 復元の情報源
  .ntkColorOverrideFaces           **フェース単位の戻し先**（JSON）
  .ntkColorOverrideSet             所属するセット名 ← 一覧を畳む単位
ntk_color_override_<対象名>_SG     上をつないだ shadingEngine
```

### 控え（シーンの隣の JSON）

`Restore` はシーンからノードを消す。 **シーンをきれいに保つのがこの操作の
目的**だが、そのままでは同じ色分けに二度と戻れない。 そこで片付ける直前に
シーンの隣へ書き出す。

```
<シーン名>.color_override.json
{ "format": 1, "tool": "color_override", "scene": "...",
  "sets": [ { "name": "hair", "items": [ {"target": "|a", "color": [1,0,0]} ] } ] }
```

**戻し先（元の shadingEngine）は書かない。** 呼び戻すのは別のセッション・
別のシーン状態かもしれないので、そのときの割り当てを見て取り直す。 古い
戻し先を持ち回ると、もう存在しない SG へ戻そうとして事故る。

**戻し先はメンバーごとに持つ。** グループノードに掛けると中のシェイプは
別々のマテリアルを持ちうるので、1 件につき 1 つでは戻せない。 v0.2.0 までは
1 つしか持たず、グループに掛けると Restore で中身が全部グレーになった。

### フェース単位の割り当て（マルチマテリアル）

**シェイプ 1 つ = マテリアル 1 つとは限らない。** フェースごとに別の
マテリアルが割り当たっているモデルでは、戻し先は「SG 1 つ」ではなく
**「(SG, そこに入っていたフェースの塊) の並び」**になる。

色を掛けるときはシェイプ全体を 1 色で塗る（v0.4.0 までと同じ）。 変えたのは
**掛ける前に分割を控えること**と、**戻すときに分割ごと復元すること**。

```
.ntkColorOverrideFaces
{"|a|aShape": [{"sg": "sgA", "components": ["|a|aShape.f[0:2]"]},
               {"sg": "sgB", "components": ["|a|aShape.f[3:5]"]}]}
```

読み取りは `instObjGroups[0].objectGroups[n]` の接続をたどる（`_read_assignment`）。

- **判別は接続プラグの形で行う。** プラグに `.objectGroups[` が含まれていれば
  フェース単位。 ふつうのシェイプは `instObjGroups[0]` が直接 SG につながる
  ので、**セットの中身を一切引かずに済む**（大きいシーンの
  `initialShadingGroup` を舐めると、掛けるたびに数千件を走査することになる）
- **塊そのものは `objectGrpCompList` から取る。** `cmds.sets(sg, q=True)` で
  SG 側から引くより安く、しかも「どの SG のどのフェースか」が接続から直接
  たどれる
- **戻すのは 2 段階**（`core.restore_plan`）。 先にシェイプ全体を土台の SG へ
  戻し、そのあとフェースの塊を割り当て直す。 順序が逆だと、どの塊にも
  入っていないフェースがオーバーライド用の SG に残り、**その SG を削除した
  時点で割り当てを失う**
- **土台はシェイプ全体に掛かっていた SG。** 全面がフェース割り当てだった
  場合は最初の塊の SG で埋める（元がどこにも割り当たっていなかった
  フェースは、戻すとその SG になる。 元の「割り当て無し」までは再現しない）
- **控えられなかったシェイプには掛けない**（`_read_assignment` の第 3 要素が
  False）。 掛けた時点で `forceElement` が元の分割を落とすので、
  読めないまま進むと戻す手掛かりがどこにも残らない。 グループを渡したとき
  中の 1 つでも読めなければ**そのノードごと飛ばす**（半分だけ掛かっている
  状態のほうが分かりにくい）。 飛ばした数は完了ログの `skipped` に出る

### 設計判断

- **復元の情報はシーンに書く。** Python 側の辞書に持つと、シーンを保存して
  開き直した時点で戻せなくなる。 シェーダーの文字列属性に書いておけば
  シーンと一緒に保存され、次に開いたときも Restore が効く。
- **管理対象の判別は名前ではなく属性の有無で行う。** `.ntkColorOverrideOriginal`
  があるシェーダーだけを対象にするので、ユーザーがノードをリネームしても
  追跡できる。 名前で判別すると、リネームされた瞬間に孤児になる。
- **掛け直しのときは既存のオーバーライドを先に探す。** そうしないと
  「オーバーライド用の SG」を「元の SG」として記録してしまい、**二度と元の
  マテリアルに戻せなくなる**。
- **既存の照会はシーンの割り当てではなく記録の索引から行う**
  （`core.index_by_object`）。 v0.2.0 で一時解除を入れた結果、**解除中は対象が
  元の SG に戻っている**ので、割り当てを辿ると既存のオーバーライドを
  見つけられない。 見つけ損なうと 2 本目のシェーダーを作ってしまう。
  索引は 1 回のスキャンで作るので、対象ごとに `listConnections` を辿るより速い。
- **対象のシェイプは `ls(dag=True, shapes=True)` で解決する。**
  `listRelatives(shapes=True)` はグループの直下にシェイプが無いと空を返すので、
  グループを渡したときに**元の shadingEngine を見つけられない**。 v0.2.0 まで
  はそこでノード自身へフォールバックし、`initialShadingGroup` を戻し先として
  記録していた（v0.3.0 で修正した不具合の原因）。
- **1 シェイプ = 1 オーバーライド を保つ。** グループに掛けたあと中の 1 つだけ
  色を変えると、そのシェイプは新しい記録へ移り、古い記録から外れる
  （`_release_members`）。 メンバーが 0 になった記録はシェーダーごと片付ける。
- **セットはシーンに、控えはファイルに。** 掛かっている間のセット名は
  シェーダーの属性（＝`Restore` で一緒に消える）。 片付けたあとの色分けは
  シーンの隣の JSON。 **シーンにツール由来のノードを残さない**という方針を
  守ったまま、「後から呼び戻す」を成立させるための分け方。
- **一覧は「掛かっているセット + 控えのセット」を並べる。** 片付けたセットが
  `控え` の行として残り、`Apply` で掛け直せる。 別に「読み込む」操作を
  作らないので、片付けたものを見失わない。
- **控えが書けなかったら片付けそのものを中止する。** 消してから
  「書けませんでした」では遅い（`_backup_sets` が `False` を返す）。
- **一覧の色は 16 進コードではなく `cmds.canvas` の色見本で出す。**
  コードを見ても何色か分からない。 値はツールチップに残す。
- **色は乱数ではなく色相を黄金比でずらして生成する。** 等間隔にすると周期で
  色が戻って 10 個目と 20 個目が同色になり、乱数にすると掛け直すたびに
  色が入れ替わって「さっきと同じものを見ている」確信が持てなくなる。
- **シーンに作るノードにも名前空間（`ntk_`）を付ける。** 実機のシーンには
  他の人が作ったノードも同居するため（CLAUDE.md「ルール」）。
- **ウィンドウ名は `<NAMESPACE>_<モジュール名>Win` 固定。** ハブがこの規則で
  古いウィンドウを閉じる。

## 機能詳細

### 0. セット
- **1 回の Apply = 1 セット。** `Set 1` のように自動命名し、一覧の名前欄を
  書き換えて Enter でリネームできる
- 一覧は**セット単位**（色見本 / 名前 / 個数 / 操作）。 まとめて掛けても
  行が増えない
- 行の操作: `Hide`/`Show`（このセットだけ一時解除）/ `Sel`（シーンで選択）/
  `Restore`（片付ける）。 控えの行は `Sel` / `Apply`（掛け直す）で、
  名前欄の右クリックから控えを削除できる

### 1. 任意色のオーバーライド
- カラースライダ、または `#RRGGBB` のテキスト入力で色を決める
- **Apply to Selected** — 選択中のオブジェクトすべてにその色を掛ける
- **グループノードを選んでもよい。** 中のシェイプを全部拾って 1 件の記録に
  まとめ、戻し先はシェイプごとに控える
- 既にオーバーライドが掛かっている対象には、**色だけを差し替える**
  （シェーダーを二重に作らない）
- 使った色は optionVar `ntk_color_override_last_color` に控え、次回起動時に復元

### 2. ランダム一括
- **Random → Selected** — 選択物に互いに見分けやすい色を振る
- **Random → All Meshes** — シーンの全メッシュに同上。
  `_BULK_CONFIRM_THRESHOLD`（50）を超えたら確認ダイアログを出す
- 既にオーバーライド済みの数を開始インデックスにするので、後から足した
  オブジェクトにも既存と重なりにくい色が付く

### 3. 一時解除（peek）
- **Hide Colors / Show Colors** — 色を一時的に外して元のマテリアルを見る。
  もう一度押すと掛け直す
- `Restore` との違いは**シェーダーとセットを消さないこと**。 記録が残るので
  何度でも往復でき、色を振り直す必要が無い
- **解除中かどうかのフラグは持たない。** shadingEngine にメンバーが居るかどうかが
  そのまま状態なので、Maya 側で手作業に割り当てを変えられても表示と食い違わない
- 解除中は shadingEngine が空になり「何に掛かっていたか」がシーンから読めなく
  なるので、外す直前に `.ntkColorOverrideMembers` へ控える
- 戻し先が同じものは 1 回の `cmds.sets` にまとめる（`core.group_by_original`）。
  対象ごとに呼ぶと数百オブジェクトで往復が効いてくる
- `color_override.toggle()` はウィンドウを開いていなくても動くので、
  **ホットキーやシェルフボタンに割り当てられる**
- 解除中に `Apply` すると、その対象だけ掛け直して色を出す
  （掛けたのに何も変わらないほうが分かりにくいため）

### 3.5 控えと呼び戻し
- `Restore` / `Restore All` は**片付ける前に必ず控えを書き出す**
- 既定の置き場所は `<シーン名>.color_override.json`（シーンと同じ場所・同じ名前）
- シーンが未保存なら「保存先を選ぶ / 控えずに片付ける / キャンセル」を尋ねる。
  **選ばれた場所は optionVar に覚える**（覚えないと書いた控えを読み戻せない）
- **どの控えを読むかは「読み込む…」で選べる。** 選択（optionVar）が既定より
  優先され、`既定` で解除する。 既定だけでは次に届かない:
  - シーンが未保存で、控えを自分で選んだ場所に置いた
  - 別名保存で置いてきた前のシーンの控えを呼び戻したい
  - 共有フォルダに置いた色分けを他の人と使い回したい
- **読めなかった控えには切り替えない。** 切り替えてから空だと、それまで
  見えていた控えまで見失う
- 控えは同名セットを上書きしながら追記される（`core.merge_catalog`）
- 掛け直しでオブジェクトが見つからないものは飛ばし、件数を警告に出す

### 4. 一覧と復元
- 一覧は**上下 2 欄**。 上が**掛かっているセット**、下が**控えだけのセット**
  - `Restore` すると上から消えて下の「控え」欄へ移る
  - 控えの行の `復元` で掛け直すと、上の一覧へ戻る
  - 同じ名前が掛かっている間、控えの側には出さない（同じものが 2 行に見える）
  - **控えが 0 件でも欄は畳まない。** 「控えたのに 0 件」のときにこそ
    「読み込む…」で探しに行きたいので、入口を隠すと詰む
  - 欄の左上に**いま見ている控えのファイル名**を出す（未保存ならその旨）
- 一覧はシーンと控えの実態から毎回作り直す（キャッシュを持たない）
- 行の `Sel` でシーン側の選択に反映する
- **Restore Selected** — 一覧で選んだ行、無ければシーンで選択中のものを戻す
- **Restore All** — シーン内のオーバーライドを全部戻す
- 元の shadingEngine が既に消えていた場合は `initialShadingGroup` へ逃がす
- 戻したあとはオーバーライド用のシェーダーとセットを削除する

### 4.5 フェース単位の割り当て（v0.5.0）
- 掛ける前にシェイプごとの**フェースの塊と戻し先**を控える
- `Restore` / `Hide` は**シェイプ全体 → フェースの塊**の順で戻す
- 控えられないシェイプには**掛けない**（警告し、完了ログに `skipped` を出す）

### 5. undo
- 掛ける／戻すはそれぞれ 1 操作 = 1 undo チャンクにまとめる
- 例外が出ても `finally` で必ず閉じる（閉じ忘れると以降の undo が壊れ、
  Maya を再起動するまで直らない）

## 制約・未対応

- リファレンスされたモデルへの割り当ては **2026-09-13 に Maya 2024 で確認済み**。
  ただし**ロックされたノード**は未検証で、割り当ての編集が禁止されていれば
  `cmds.sets` がエラーになる可能性が残る
- インスタンスされたシェイプは考慮していない（1 つ塗ると全インスタンスに乗る）
- フェース単位の割り当て（マルチマテリアル）は **v0.5.0 で復元できるように
  した（実機未確認）**。 掛けるときは従来どおりシェイプ全体が 1 色になる
  （フェースを選んで色を分けることはできない）。 元が**割り当て無し**だった
  フェースは、戻すと土台の SG に入る（「割り当て無し」までは再現しない）
- **v0.4.0 以前に掛けたままのシーンには、フェース分の控えが無い。**
  そのまま v0.5.0 で Restore すると従来どおりシェイプ全体が 1 つの SG に
  寄る（後から復元する手立ては無い）
- **v0.2.0 以前に掛けたオーバーライドが残っているシーンは、グループに
  掛けた分の戻し先が `initialShadingGroup` として記録されている。**
  v0.3.0 で開いても記録そのものは直せない（元の情報がどこにも無い）。
  該当するシーンは Restore せずに開き直すこと
- `surfaceShader` 固定。 陰影付き（`lambert`）への切り替えは未実装

## 実装状況

**確認済みは Maya 2024 のみ。 2025 は全版とも未確認**（会社では 2024 と 2025 の
両方を使うので、これは残っている宿題）。

### v0.7.0
- **読み込む控えを選べるようにした**（控え欄の `読み込む…` / `既定`）。
  実機からの要望「同じディレクトリの控えを読み込むようになっているが、
  読み込む控えを選択できるようにしたい」
- 選んだ控えは**既定（シーンの隣）より優先**する。 v0.6.0 は未保存シーンの
  ときしか optionVar を見なかったので、選んでも既定に戻ってしまっていた
- **控えが 0 件でも欄を畳まなくした。** v0.6.0 は空なら欄ごと隠していたが、
  それでは「控えたのに 0 件」の状態から**選び直す入口に届かない**
- 欄の左上に**いま見ている控えのファイル名**を出す。 「0 セット」だけでは
  未保存なのか空なのか別の控えを見ているのかが分からない
- **実機未確認。** 実機では次を確かめる:
  1. **未保存シーン**で Restore → 保存先を選ぶ → その控えが控え欄に出るか
     （ファイル名も出るか）。 `0 backup` のままになっていないか
  2. `読み込む…` で別の控え（前のシーンのもの）を選ぶ → 控え欄に並ぶか →
     `復元` で掛かるか
  3. `既定` でシーンの隣に戻るか（シーン未保存なら「未保存です」の表示に戻るか）
  4. 壊れた JSON / 空の JSON を選んでも切り替わらず、警告だけ出るか

### v0.6.0
- **一覧を「掛かっているセット」と「控え」の 2 欄に分けた。** `Restore` した
