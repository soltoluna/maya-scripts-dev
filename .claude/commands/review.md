対象を6つの観点で並列レビューしてください。

対象: $ARGUMENTS

## 手順

### 1. 対象ファイルを決める

**このステップでソースコードを読まないこと。** ファイル名の一覧を作るだけです。
本文を読むのはサブエージェントの仕事で、ここで読むと同じ内容が7重に読み込まれます。

引数の解釈:

- **ファイルパス** (`rename_helper/rename_helper/ui.py`) → そのファイルのみ
- **ツールフォルダ名** (`rename_helper`) → そのフォルダ内の `.py` 全部
  （`install.py` とパッケージ内の `.py`。`tests/` は除く）
- **省略** → `git status --short` と `git diff --name-only HEAD` から、今セッションで
  変更した `.py` を対象にする。変更が無ければ直近コミット(`git log -1 --name-only`)で
  触れたツールの `.py` を対象にする

決まったら「対象: <ファイル一覧>(N件, 合計M行)」と表示してから次へ進む。

### 2. 規模を確認する

対象の合計行数を数える。**2,000行を超える場合は起動せず**、絞り込み案を提示して
ユーザーに確認する。

### 3. 6観点を並列起動する

以下6つを**1回のメッセージで同時に**起動する(順番に呼ばない)。
各サブエージェントには**手順1で決めたファイルパスの一覧を明示的に渡す**。
「このツールをレビューして」ではなく「次のファイルをレビューして: <一覧>」と伝える。

- `maya-functionality` — 機能性・要件適合度
- `maya-ux` — UI/UX・ワークフロー統合
- `maya-performance` — パフォーマンス・スケーラビリティ
- `maya-code-quality` — コード品質・保守性
- `maya-reliability` — 安定性・エラーハンドリング
- `maya-distribution` — 配布・更新・拡張性

`SPEC.md` がある場合はそのパスも併せて渡す。

### 4. 集計する

```
# <対象> レビュー結果

対象ファイル: N件 / M行

| 観点 | スコア |
|---|---|
| 機能性・要件適合度 | N/5 |
| UI/UX・ワークフロー統合 | N/5 |
| パフォーマンス・スケーラビリティ | N/5 |
| コード品質・保守性 | N/5 |
| 安定性・エラーハンドリング | N/5 |
| 配布・更新・拡張性 | N/5 |
| **総合** | **N.N/5** |

## 優先して対応すべき指摘
(全観点の CRITICAL と WARNING を深刻度順に最大5件。観点名を併記)

## 観点別の詳細
(各サブエージェントの出力を観点ごとに掲載)
```

総合スコアは6観点の単純平均を小数第1位まで。

## ルール

- スコアと指摘は**サブエージェントの出力をそのまま使う**。集計時に点数を調整したり
  指摘を書き換えたりしない。
- 複数の観点が同じ箇所を指摘した場合は「優先して対応すべき指摘」でまとめ、どの観点から
  挙がったかを併記する。
- この時点では**コードを修正しない**。結果の提示で止め、修正するかはユーザーの指示を待つ。
- 結果をファイルに保存しない。`SPEC.md` や `PROGRESS.md` も更新しない。
- **レビューは実機確認の代わりにならない。** サブエージェントは Maya を持っていないので、
  指摘はすべて静的な読みに基づく。集計の最後にその旨を1行添える。

## 所要時間の目安

数百行のツールなら1〜2分。**3分を超える場合は対象が大きすぎる**ので、中断して対象を
絞り直したほうが早い。
