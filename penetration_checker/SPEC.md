# Penetration Checker — 詳細仕様

## 概要
- バージョン: 0.1.0 / 対応Maya: 2024+
- カテゴリ: Animation
- 表示場所: シェルフボタン `PenetChk`（左クリックで起動。 ドロップしたときに開いていたシェルフに貼られる）
- 指定した複数のオブジェクト／グループ配下のメッシュ同士のめり込みを現在のフレームで調べ、
  めり込みに最も効いているコントローラー（無ければジョイント）を選択する。 シーンは変更しない。

## アーキテクチャ

```
../install.py       リポジトリ直下のハブ。 全ツールをまとめて配る（触らない）
penetration_checker/
  __init__.py       __version__（版数の唯一の情報源）/ SHELF_LABEL / show() / diagnose()
  core.py           Maya 非依存の純ロジック ← 自宅でテストできるのはここだけ
                    ボックス・内外判定・スコア集計・コントローラー探索（グラフは関数で受け取る）
  scene.py          シーンを読む層（OpenMaya 2.0 + cmds）。 値を取って core に渡すだけ
  ui.py             cmds による UI。 scene.check の結果を一覧と選択に流すだけ
  dev_tools.py      バージョン表示と「GitHub から更新」（全ツール共通・触らない）
```

### 処理の流れ（`scene.check`）

1. 対象ノードを配下のメッシュ（中間オブジェクト・非表示を除く）に展開する
2. 各メッシュのワールド頂点座標（変形後）を `MFnMesh.getPoints(kWorld)` で読み、
   点からバウンディングボックスを作る
3. ボックスが重なる組だけを候補にする（`core.candidate_pairs`）
4. 候補の組 (A, B) の両方向について、**A の頂点が B の内側にあるか**を調べる
   （`core.find_inside_vertices`）。 B のボックス外の頂点は問い合わせない
5. めり込んでいる頂点（深い順に最大 200）のスキンウェイトを集計し、組ごとに
   最も効いているインフルエンスを 1 つ選ぶ（`core.influence_scores`）
6. インフルエンスから上流へコントローラーを探す（`core.find_controller`）
7. 同じコントローラーをまとめて順位を付ける（`core.aggregate_targets`）

### 設計判断

- **内外判定は「最近接点 + 法線の符号」。** 頂点 p と、相手メッシュ上の最近接点 c・
  そこの外向き法線 n について `(p − c)·n < 0` なら内側。 深さは `−(p − c)·n/|n|`。
  レイキャストの偶奇判定より速く、深さもそのまま取れる。 頂点だけを見るので、
  頂点が外にあって辺だけが面を突き抜けるケースは拾わない（v0.1.0 の割り切り）。
- **開いたメッシュは既定で「めり込まれる側」にしない。** 1 枚布の裏側を内側と
  みなすと、服の下にある体の頂点がすべて「服の中」と判定される。 開いたメッシュの
  頂点が閉じたメッシュに刺さっている向きは調べるので、体を突き抜けた布は拾える。
  UI のチェックで「裏側 = 内側」として扱うこともできる。
- **座標は内部単位（cm）で統一する。** `getPoints(kWorld)` は UI の単位設定に
  関係なく cm で返す。 `cmds.exactWorldBoundingBox`（UI 単位）と混ぜないよう、
  ボックスも点から作る。 許容値の入力と深さの表示だけ `MDistance` で変換する。
- **スコアは `Σ weight × (depth + ε)`。** 深く刺さっている頂点を強く効かせる。
  浅く触れているだけの頂点が数で勝つと、直すべき場所からずれるため。
- **コントローラーの探索は幅優先で「入力接続 → DAG の親」。** 最初に当たったものを
  採る。 コントローラーの条件は「`controller` タグが付いている」か「NURBS カーブの
  シェイプを持つトランスフォーム」。
  - **ジョイントからは DAG の親を辿らない。** 辿ると親ジョイント側の
    コントローラーを拾ってしまう
  - 接続のうち `message` / `inverseScale` / `drawOverride` などは動きの出どころでは
    ないので無視する
  - mGear 型（ジョイント ← decomposeMatrix ← matrixConstraint ← ロケーター）は、
    ロケーターから DAG の親を登ってコントローラーに当たる
  - 見つからなければインフルエンス自身（= ジョイント）を選ぶ。 スキンの無い
    メッシュはメッシュのトランスフォームから同じ探索をする
- **シーンを変更しない。** 結果として変わるのは選択だけ。 undo チャンクは開かない。
- **実機で想定と違ったときのために `diagnose()` を置く**（CLAUDE.md「推測で直さない」）。
  既定でシーンを変更せず、例外は `<ERROR ...>` にして最後まで出す。

## 機能詳細

### 1. 対象の指定
- 「選択を追加」で選択中のノードをリストに登録する（グループ可。 配下のメッシュ全部が対象）
- リストが空なら、チェック時に選択中のものを対象にする
- リストの行をクリックすると、そのノードを選択する

### 2. 判定（「現在のフレームを調べる」）
- 対象のメッシュを総当たりで調べる（ボックスが重ならない組は飛ばす）
- 許容する深さ: これ以下のめり込みは無視（シーンの単位）
- 開いたメッシュも「内側」があるものとして調べる（既定オフ）
- 非表示のメッシュを除く（既定オン）
- プログレスウィンドウで進捗を出し、Esc で中断できる（途中までの結果を出す）

### 3. 結果
- 影響の大きい順に `[CTRL|JNT|OBJ] 名前  頂点数  最大深さ  (刺さっている側 > 刺さられている側)`
- 「最も影響の大きいコントローラーを自動で選択」がオンなら、1 位を選択する
- 行をクリック / 「コントローラーを選択」でその行のノードを選択
- 「めり込み頂点を選択」でその行に関わるめり込み頂点を選択

### 4. 調査関数
- `penetration_checker.diagnose()` — 選択中のノード（メッシュ / ジョイント / コントローラー）
  について、上流の接続・コントローラー判定・探索結果・スキン・閉じているか・
  最近接点の戻り値を Script Editor に出す

### 5. 設定の保存（optionVar）
- `ntk_penetration_checker_tolerance` / `_open_containers` / `_skip_hidden` / `_auto_select`

## 実装状況

### v0.1.0
- 初版。 上記 1〜5 を実装。 **実機未確認**（Maya 2024 / 2025 とも）。
- 自宅で検証済み: `core` の判定・集計・探索（球と手書きのグラフ）、UI の配線（scene は偽物）
- 実機で確かめること:
  1. 2 つの球を重ねて調べると、深さが正しく出る（cm 以外の単位設定でも）
  2. スキンされたキャラクターで、手を体に刺したときに手のコントローラーが選ばれる
  3. コントローラーの無いリグ（ジョイントを直接動かす）でジョイントが選ばれる
  4. 期待と違うときは `diagnose()` の出力を取る
  5. 重いシーンでの所要時間（頂点数の多いメッシュ同士）
- 未対応（候補）: フレーム範囲のスキャン、辺の貫通、1 メッシュ内の自己交差
